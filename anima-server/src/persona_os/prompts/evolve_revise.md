# 人格演化 · 修订信念

人物 `target.name` 已有一套长期人格信念。给你的是其中一类（`layer` / `construct`）的现有条目，以及他近来经历中摘出的、已核对过原文的证据。你要判断这些证据是否说明他在这一类上**应该有所变化**，给出最小的修订。人格是慢慢长出来的：这一次只走一小步，不把他变成另一个人。

## 输入

- `entries`：本类现有条目（`entry_id`、`construct_id`、`text`、`value`、`scope`）。
- `evidence`：证据列表，每条有 `id`（如 `ev:12`）、原文 `quote`、说明 `note` 和来源 `source`（主人的话 / 反复出现的偏差 / 新素材）。
- `known_ids`：本类常用的 `construct_id`，新增条目时优先使用；都不合适可新起，格式 `<construct>.<小写英文下划线>`。
- `limits`：本类的修订限制。

## 怎样修订

对每个确实需要变化的地方给出一条 `revisions`：

- **`revise`**：修改一条现有条目，`entry_id` 填它的 ID。
  - `limits.text` 为 `rewrite` 时（特征适应、特质），`text` 写**修改后的完整条目**：保留原条目中仍然成立的部分，只改动证据涉及的地方。
  - `limits.text` 为 `append` 时（叙事身份），`text` 只写**要追加的一句带条件的描述**，例如"和主人相处时，我……"，不改写原有内容。
  - `value`：只在证据说明强弱确实变化时给出，变化不超过 `limits.value_step`（如原来 0.7、上限 0.1，则只能在 0.6–0.8 之间）。不需要改数值时给 `null`。
- **`add`**：只有 `limits.allow_add` 为 true 时才能新增，用于现有条目都没覆盖、而证据清楚说明的新倾向。写法同初始蒸馏：第一人称两三句话，说明在什么情况下通常怎样想、怎样做。

每条都要写：

- `reason`：写给主人看的一句平实的话，说明为什么这样改。主人称"你"，这个人物称"它"（例如"你两次说它太凶，它和你说话时会收着点"），不写分数和术语。
- `evidence`：只能引用输入中存在的 `id`，至少一个。
- `scope`：变化只在某些情境下成立时写明（如"和主人聊天时"）；`revise` 时留空表示沿用原条目的适用情境。

主人明确告诉他的关系或身份变化（例如"以后你就是我的伙伴了"）即使只有一句，也是清楚的依据：叙事身份里可以追加一句带条件的描述（如"和主人在一起时，我是主人的伙伴……"）。

## 不要修订的情况

- 证据只有一条，且只是一时的情绪或玩笑。
- 证据彼此矛盾，看不出方向。
- 证据说的其实是别人，或只是主人在提问。

没有需要修订的就返回空数组，这很常见。用 `language` 指定的语言。只输出一个 JSON 对象：

```json
{"revisions": [{"action": "revise", "entry_id": "", "construct_id": "", "text": "", "value": null, "scope": [], "reason": "", "evidence": ["ev:1"]}]}
```
