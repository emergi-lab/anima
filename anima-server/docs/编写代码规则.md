# 编写代码规则

更新日期：2026-10-28

1. 每次代码变动同步更新本文件与 `未修复.md`，说明改动、验证结果和遗留问题；接口变化同步 `接口契约.md`。
2. 计划只放在 `未修复.md`，不另建 Plan 文档。
3. 人格引擎（`application/engine.py` 等）保持通用，不出现桌宠概念；桌宠与蒸馏放在各自模块，用通用字段（情境、观察、任务、extra_schema）调用引擎。
4. 每次行动默认 2 次模型调用（状态推断；生成 + 复核），调用方可要求合并为 1 次 `respond` 调用（桌宠聊天使用，换取一半延迟）；事件关闭后每个人格另有 1 次课后整理调用（记忆 + 监测），不属于行动。每个调用最多 2 次尝试（调用 2 的第二次尝试也用于程序检查未过的重做，带上检查意见）；仍失败如实返回 502/503，不伪造输出、不加第三种调用。
10. 输出语言以 situation.language 为准；信念材料是中文不改变输出语言。非中日文情境下，发言与解释出现中文即视为检查未过。
5. 信念只能由构建（导入）、演化提交（候选审核或演化蒸馏）与回到旧版本写入；状态只由执行引擎写入；版本只增不改。
6. 不得把测试输出、执行建议或主人的自由文字（note）当作演化证据；重复的总结按同一来源计数。
7. 人格库不保存用户的真实身份信息（邮箱、证件号等）；日志记录原因、位置、人格 ID、尝试次数与用量，不记录完整信念、凭据和模型原文。
8. 每次模型调用记录请求指纹、提示词版本哈希、模型名、token、耗时、重试次数。
9. 优先复用、不堆积代码；按任务维护最小必要测试，覆盖接口入口、错误边界、幂等与不重复提交。
