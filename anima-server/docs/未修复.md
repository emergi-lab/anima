## 2. A1 蒸馏（设计经用户确认，2026-10-22 实现）

用户决定（2026-10-22）：由用户指定蒸馏对象；素材规模为几十万字；工作台可以直接改写条目；模型用 flash。

### 2.1 流水线

| 步骤 | 做法 | 模型调用 |
|---|---|---|
| ① 导入素材 | 上传一个或多个 UTF-8 文本；按空行、场景标记切成约 3000 字的片段，记录文件与字符位置 | 无 |
| ② 指定对象 | 程序统计"名字："一类说话人标记，给出候选角色及出现次数；用户选定目标，并补充别名（如"小希 / 希希 / 林希"） | 无 |
| ③ 筛选 | 保留目标说话或被提到的片段，并带上相邻片段作为上下文；在工作台显示筛选后的字数与预计用量 | 无 |
| ④ 证据抽取（map） | 每个片段 1 次调用：摘出能体现目标人格的原句，写明它说明了什么，并标注可能的层级与构念；程序校验原句必须逐字出现在片段中，不符合的丢弃 | 每片段 1 次，可并发 |
| ⑤ 归纳（reduce） | 按 8 个构念类别各 1 次调用，把证据归纳成信念条目（第一人称文本、适用范围、置信度，引用证据编号）；某类证据过多时先分批归纳，再合并 | 约 8–16 次 |
| ⑥ 复核 | 1 次调用检查条目之间的矛盾、过度概括和缺少证据的结论，给出修改建议；程序检查引用是否存在、构念是否合法 | 1 次 |
| ⑦ 审阅 | 工作台逐条显示：条目、置信度、证据原句（可点开看所在片段的上下文）、复核意见。用户可以通过、驳回、改写，也可以新增条目 | 无 |
| ⑧ 确认 | 已通过与改写过的条目导入为 B0（`personas:import`）；被引用的证据作为 material 一并保存；证据不足的构念保留 `unknown` | 无 |

- 条目来源：模型归纳的为 `inference`；用户新增的为 `configured`；用户改写的条目仍标为 `inference`，保留原证据，另记一条改写记录。
- 用量估计：30 万字约 20 万 token，筛选后约一半，④ 约 30–50 次调用，⑤⑥ 约 10–20 次。总计约 30–40 万输入 token；按 4 路并发，约 5–10 分钟。
- 任务在后台执行，可以续跑：每个片段的抽取结果单独保存，中断后从未完成的片段继续；工作台显示进度与已用 token。

## 8. 聊天台词先出、窗口不跟随、工作台步骤（2026-10-23）

- 台词先出：`respond` 的输出顺序改为 `final` → `state` → `review` → `action_basis`（曾试过先写一句 `now` 再写台词，用户要求去掉：台词直接按结构化提示词输出；对比实测两者出台词时间无明显差别，3.80 秒对 4.02 秒）。模型偶尔把 `dropped` / `unknown` 写在 `state` 外层，解析时移回 `state`。OpenAI 模型用流式接收，`final` 对象一完整（程序核对括号与字符串转义）且通过检查就交给 `Engine.prepare(early=…)`；聊天服务立即返回台词，状态 / 复核 / 依据在后台写完后存档并提交，人格的锁一直持有到提交，下一句、`chat:end`、闲置清扫都排在其后。台词已显示而其余输出失败时，仍存已显示的台词（状态为空、`state_issue` 注明），不会换成另一句。`ChatReply` 不再带 `usage`。

## 13. 大五人格蒸馏优化、自我反思（2026-10-23）

开放性缺失的原因（八戒、悟空的特质都恰好 6 条）：特质只有一次归纳调用，几百条特质证据抽样到 200 条后要求"一般 1–6 条"，15 个分面只剩证据最多的 6 个；抽取提示词对开放性只写了"好奇或保守"；也没有维度覆盖检查。数据库里其实有开放性证据（悟空"选择学更多的变化""博学多识""因好奇扯开铃铛"）。用户决定不做"补全"，只优化蒸馏过程：
- 抽取提示词按大五五个维度列出要看的言行（开放性：好奇求知、爱学新本事、想象与点子、变通、喜新或守旧、审美），特质证据必须标 `facet`。
- 特质按维度分五次归纳（每次只给该维度的分面）。
- 某维度特质证据少于 3 条时，挑提到人物最多的 6 段，只针对该维度补查（`ExtractInput.focus`）；补查只在同一维度内去重（一句话可同时体现价值和某个维度）。预估调用次数相应增加（补查不计入预估）。
