# anima-server 接口契约 v1

更新日期：2026-10-22　继承自 ustc-persona 接口契约 v1；§7 蒸馏为 Anima 新增，桌宠接口待补。

本服务只实现人格：按 EMERGI-PersonaOS 管理人格对象（三层信念与版本、当前状态、记忆、监测、反思、受控演化）。
人格引擎不出现桌宠或场景概念；这些由调用方用通用字段表达，桌宠的映射见附录 A。

---

## 0. 通用约定

- 基础路径 `/v1`；JSON，UTF-8；时间为 ISO 8601（带时区）。
- 鉴权：`Authorization: Bearer <服务令牌>`。每个令牌属于一个**命名空间**（Anima 只用 `anima`），人格、事件、反馈都隔离在命名空间内。本服务不处理终端用户登录，"谁能看哪个人格"由调用方检查。
- 标识由调用方给定，作为幂等键：`persona_id`、`episode_id`、`action_id`、`feedback_id`。相同键 + 相同内容重复提交返回原结果；相同键不同内容返回 409。
- 错误格式：`{"error": {"code": "...", "message": "...", "retryable": false}}`
  - 400/422 请求不合法；404 不存在；409 冲突（幂等键内容不同、事件已关闭、版本已变化）；
  - 502 `generation_failed`（模型输出在有限重试后仍不合格，**不伪造输出**）；503 `model_unavailable`（可重试）。
- 人格内容中不含姓名、学号等身份信息；导入时出现常见身份字段直接拒绝。

## 1. 核心对象

### 1.1 信念条目 BeliefEntry（论文附录 C.1）

```json
{
  "entry_id": "L2_need_autonomy",
  "layer": "L2",
  "construct": "need",
  "construct_id": "need.autonomy",
  "value": {"satisfaction": 0.167, "frustration": 0.667, "scale": "0-1"},
  "text": "在可以自行决定方法时，我通常很难感到自己能够按真实意愿行动……",
  "source": "measurement",
  "source_ref": {"instrument": "DIGITAL_TWIN_PERSONALITY_ASSESSMENT_V1_FOUR_POINT", "administered_at": null},
  "evidence_refs": [],
  "confidence": 0.8,
  "scope": ["自主选择情境"],
  "modifiable": true,
  "epistemic_status": "supported",
  "runtime_policies": []
}
```

| 字段 | 说明 |
|---|---|
| `layer` / `construct` | 固定分类（论文表 C.1），不接受新类别：L3 `overall_identity` `imago` `life_course`；L2 `need` `value` `goal` `strategy`；L1 `trait` |
| `construct_id` | 具体构念，如 `imago.sage`、`value.benevolence`、`strategy.planning`、`trait.extraversion.sociability` |
| `value` | 数值字段带 `scale`；未知为 `null` 且 `epistemic_status = unknown` |
| `source` | `measurement`（须带量表与施测记录）/ `inference`（由材料推断）/ `configured`（人工设定）/ `generated`（系统生成） |
| `epistemic_status` | `supported` / `unknown` / `pending` |
| `runtime_policies` | 演化时编译的运行时策略（论文 B.2），初始为空 |

### 1.2 信念版本 BeliefVersion

`version_id`、`persona_id`、`k`（0 起）、`base_version_id`、`origin`（`construction` / `evolution` / `correction`）、`candidate_id`、`committed_at`、`entries[]`。版本只增不改。

### 1.3 人格状态 PersonaState（每次行动一份快照）

```json
{
  "L3": {"identity_position": "...", "responsibilities": ["..."], "event_meaning": "...",
         "active_imago": {"construct_id": "imago.sage", "activation": "high", "target": "p3", "role": "..."},
         "refs": {"entries": ["L3_imago_1"], "evidence": ["obs:12", "mem:7"]}},
  "L2": {"needs": [{"construct_id": "need.competence", "now": "frustrated", "cause": "...", "refs": {}}],
         "values_activated": [], "goal_priorities": [], "strategy": {"chosen": "...", "why": "...", "refs": {}}},
  "L1": {"expressions": [{"construct_id": "trait.extraversion.assertiveness", "direction": "high",
                          "channel": "language", "target": "p3", "evidence": ["obs:12"]}]},
  "cross_check": "...", "dropped": ["..."], "unknown": ["..."]
}
```

每一项都链接到信念条目与证据（观察、记忆）。快照记录所用信念版本。

### 1.4 事件 Episode 与观察 Observation

事件 = 一段有始有终的情境（论文的事件尺度）。观察 = 事件中发生的、所有参与者都可见的事（别人说的话、情境变化），按调用方给的递增序号 `seq` 排序。

## 2. 人格构建

### `POST /v1/personas:import`

```json
{
  "mode": "create_only",
  "personas": [
    {"persona_id": "student-283",
     "entries": [ /* BeliefEntry[]，覆盖所需构念；缺失的构念由服务补为 unknown */ ],
     "material": [{"ref": "profile:283#identity", "text": "第一人称材料（可选，作为 inference 证据）"}]}
  ]
}
```

- `mode`：`create_only`（已存在则跳过）/ `replace_initial`（仅在没有任何演化版本时替换 B0）。
- 返回每个人格的 `version_id`（k=0）与校验结果。问卷到条目的转换由调用方完成（附录 A.1）。

### 读取
- `GET /v1/personas/{persona_id}`：当前生效版本、条目数、未知构念、待审核候选数。
- `GET /v1/personas/{persona_id}/versions`、`GET /v1/personas/{persona_id}/versions/{version_id}`。

## 3. 情境中的行动（算法 1，每次行动默认 2 次模型调用，可合并为 1 次）

### `POST /v1/episodes`

```json
{
  "episode_id": "s03-w03-table-01",
  "situation": {"title": "...", "description": "情境与任务背景（自然语言）", "language": "zh"},
  "participants": [
    {"participant_id": "p1", "display_name": "小澄", "persona_id": "student-283",
     "position": {"identity": "组长", "responsibilities": ["推进讨论进度", "确保每人发言"]}},
    {"participant_id": "p2", "display_name": "阿远", "persona_id": "student-532", "position": null}
  ]
}
```

- `position` 是此人在本事件中的情境身份与责任，进入**状态**（L3 当前身份位置），不写入信念。
- 服务为每个人格载入上次调和后的状态与生效版本。一个人格同一时间只能处于一个未关闭事件。

### `POST /v1/episodes/{episode_id}/observations`

```json
{"items": [
  {"seq": 12, "kind": "utterance", "actor": "p2", "content": "……", "addressed_to": ["p1"], "at": "..."},
  {"seq": 13, "kind": "event", "actor": null, "content": "进入观点交换：请回应他人的具体理由", "at": "..."}
]}
```

`seq` 必须递增；人格自己已提交的行动不需要再报（由 commit 写入）。

### `POST /v1/episodes/{episode_id}/actions:prepare`（核心）

```json
{
  "action_id": "s03-w03-table-01-t005",
  "participant_id": "p1",
  "upto_seq": 13,
  "task": {"instruction": "回应 p2 的理由，说明同意或不同意的具体点", "intent": "p2 刚点名你"},
  "output_contract": {
    "length": {"unit": "words", "soft": [55, 80], "hard": [25, 160]},
    "extra_schema": { /* JSON Schema：调用方需要人格一并填写的结构化字段 */ }
  }
}
```

服务内部流程：锁定生效版本 → 组织情境证据（`seq ≤ upto_seq` 的观察）→ 程序检索记忆（≤6 条，只取事件开始前已存在的）→ **调用 1 状态推断** → **调用 2 生成 + 复核** → 程序检查（硬长度、addressed_to、extra_schema、输出语言 = `situation.language`）。每个调用最多 2 次尝试，调用 2 的第二次尝试也用于带检查意见的重做；仍不合格返回 502，模型不可用返回 503，不伪造。`usage.model_calls` 等于请求的 `calls`，`attempts` 为实际尝试次数。

请求可带 `"calls": 1`（默认 2）：状态推断与生成 + 复核合并为一次 `respond` 调用（输出顺序 `final` → `state` → `review` → `action_basis`，进程内调用方可在 `final` 写完时提前拿到台词），输出同样包含状态 Z_t、复核、`final` 与 `action_basis`，存储与解释方式不变；延迟约为两次调用的一半，状态写得更简略。桌宠聊天（§8）使用这一方式。程序检查与重做规则相同。

响应：

```json
{
  "action_id": "s03-w03-table-01-t005",
  "status": "prepared",
  "output": {"text": "……", "addressed_to": ["p2"], "extra": { /* 按 extra_schema 填写 */ }},
  "belief_version_id": "...",
  "state_id": "...",
  "usage": {"model_calls": 2, "attempts": 2, "prompt_tokens": 12000, "completion_tokens": 1800, "latency_ms": 9000}
}
```

`prepared` 的结果不进入人格的经历，直到 commit。

### `POST /v1/episodes/{episode_id}/actions/{action_id}:commit`

`{"seq": 14, "published_text": null, "at": "..."}` —— 调用方实际发布后调用；`published_text` 为空表示与准备内容一致。写入最终状态快照、把行动作为观察入账并关联信念版本。

### `POST /v1/episodes/{episode_id}/actions/{action_id}:discard`

调用方放弃这次准备（暂停、结束、插入指令等）。只保留为生成记录，不进入经历。

### `POST /v1/episodes/{episode_id}:close`

```json
{"outcome": {"text": "事件结果（可选，如讨论结论）"}, "reflect_no_later_than": "2026-10-22T14:00:00+08:00"}
```

关闭后不再接受行动。触发课后任务：每个人格 1 次调用（`consolidate`）写情节/关系记忆 + 状态监测，后台执行，关闭接口立即返回。反思在"该人格的反馈已完成"时执行（只由主人完成反馈触发，`reflect_no_later_than` 保留但不使用）。

- 情节记忆：本事件经过（3–5 句，引用 `obs:<seq>`）。关系记忆：只记与**其他人格参与者**的直接交流（跨事件按 persona_id 找回）。
- 状态监测：本人发言与信念条目明显偏离（`above` / `below` / `contrary`），只能引用本人发言为证，情境身份要求的行为不算偏离；结果供反思使用，不直接修改信念。
- 模型输出中不存在的引用（观察、条目、参与者）一律丢弃。
- 之后每次 `actions:prepare` 的调用 1 会收到记忆（最近 3 个其他事件的情节记忆 + 与本事件在场人格各最近 1 条关系记忆），引用为 `mem:<id>`；当前事件自身的记忆不会被召回。

### `GET /v1/episodes/{episode_id}/jobs`

课后任务状态：`[{"persona_id","job":"consolidate","status":"pending|running|done|failed","runs","error","updated_at"}]`。失败时同时发出 `episode.jobs_failed` 事件。

### `POST /v1/episodes/{episode_id}/jobs:run`

仅限已关闭事件：补建缺失的课后任务（如 S3 之前关闭的事件），并把失败的任务重新排队；返回任务列表。重跑替换该事件已有的记忆与监测，不会重复。服务重启时，未完成的任务自动继续。

### `GET /v1/personas/{persona_id}/memories?limit=50`

`[{"memory_id":"mem:12","episode_id","kind":"episodic|relational","about_persona_id","about_name","text","evidence","created_at"}]`，新到旧。

### `GET /v1/actions/{action_id}/explanation`

"为什么这么说"：状态链与行动依据（文字说明 + 引用的信念条目文本），默认不含数值。

## 4. 主人反馈

### `PUT /v1/feedback-taxonomies/{name}`

```json
{"judgments": ["endorse", "partial", "reject"],
 "reasons": [
   {"code": "too_harsh", "label": "太冲了，我没这么硬", "target": "L1"},
   {"code": "wording_only", "label": "意思对，但我不会这么讲", "target": "wording"},
   {"code": "too_polished", "label": "说得太漂亮了", "target": "systemic"},
   {"code": "never_happened", "label": "它提到的事我没有过", "target": "fact_check"}
 ]}
```

`target` 取值：`L1` / `L2.strategy` / `L2.need` / `L2.value` / `L3` / `wording`（只调表达，不改人格）/ `systemic`（系统通病）/ `fact_check`（核对来源）/ `none`。

### `POST /v1/feedback`

```json
{"feedback_id": "...", "persona_id": "student-283", "action_id": "s03-w03-table-01-t005",
 "taxonomy": "anima-v1", "judgment": "reject", "reason_code": "too_harsh",
 "note": "换我会说……", "submitted_at": "..."}
```

`note` 只存档，**永远不作为修改人格的证据**。

- 只能评人格自己**已提交**的行动（否则 404）；每个行动最多一条反馈（另一个 `feedback_id` 评同一行动 409 `feedback_conflict`）。
- 主人完成本事件反馈前，同一 `feedback_id` 可以重新提交来修改（以最后一次为准）；完成后 409 `feedback_closed`。
- 分类不存在 404 `taxonomy_not_found`；判断或原因不在分类中 422。原因的 `target` 随反馈保存，供反思使用。

### `GET /v1/episodes/{episode_id}/feedback?persona_id=`

`{"episode_id","persona_id","completed_at":null|时间,"items":[FeedbackCreate...]}`。该人格不在事件中 404。

### `POST /v1/episodes/{episode_id}/feedback:complete`

`{"persona_id": "student-283"}` —— 主人对本事件的反馈已完成，可立即反思。重复调用无副作用，返回 `{"status":"completed"}`。完成后该人格在本事件的反馈锁定。

## 5. 受控演化（算法 2）

反思结果：`retain`（只给执行建议）/ `defer`（记下观察条件）/ 生成修订候选。候选依次经过证据审查、约束审查、冻结副本测试，通过后进入 `awaiting_owner`。

实现（2026-10-22）：
- **触发**：主人 `feedback:complete` 后排入该人格的 `reflect` 任务（`GET /episodes/{id}/jobs` 可见）；若本事件的课后整理还没完成，等它完成再反思。服务启动时，已完成但还没有反思任务的反馈会补排。
- **证据（程序计数）**：①同一原因、指向人格层（`L1` / `L2.*` / `L3`）的未用过反馈 ≥3 条，只计主人已完成的事件；②同一条目、同一方向的监测偏离出现在 ≥2 个事件。措辞、通病、事实核对、说不上来不计。已被任何候选引用的证据不再使用。
- **反思**：有证据时 1 次调用（`prompts/reflect.md`），每组证据给出一个最小修订或暂缓；没有证据时不调用模型，结果为 `defer`。
- **约束审查（程序）**：只改当前版本中存在、supported、可修改且层一致的条目；L1 只改 `value.baseline`；L2 可改 `value.baseline` / `value.satisfaction` / `value.frustration`；L3 只能 `text.append`。幅度超出学期余量时截到余量，小于 0.01 丢弃。
- **冻结副本测试**：6 个情境（目标 / 相似 / 范围外各 2 个，由反思调用给出），修订前后各从空状态、无记忆起步完成同一任务（每次 2 次调用，共 24 次），再由 1 次调用（`prompts/judge_tests.md`，温度 0）判定。事前固定的标准：至少 1 个目标情境 `realized` 且所有范围外情境 `unchanged` → `awaiting_owner`；目标都未显现 → `pending_realization`；范围外有变化 → `no_commit`。
- `strength`：证据来自多个事件为 `strong`，否则 `limited`。

### `GET /v1/personas/{persona_id}/candidates?status=awaiting_owner`

```json
{"candidate_id": "...", "base_version_id": "...", "layer": "L1",
 "summary": "在别人直接否定你时，回应会更收着一些，先承认对方的部分道理",
 "edits": [{"entry_id": "L1_agreeableness_respectfulness", "field": "value.baseline", "from": 0.33, "to": 0.43}],
 "scope": ["被当面否定时"],
 "evidence_for": [{"kind": "feedback", "ref": "...", "quote": "太冲了，我没这么硬"}],
 "evidence_against": [],
 "strength": "limited",
 "test": [{"type": "target", "situation": "...", "before": "...", "after": "...", "verdict": "realized"},
          {"type": "out_of_scope", "situation": "...", "before": "...", "after": "...", "verdict": "unchanged"}],
 "status": "awaiting_owner"}
```

`edits` 中的数值供调用方内部使用，面向主人的展示用 `summary` 与 `test`。

### `POST /v1/candidates/{candidate_id}:decide`

`{"decision": "approve" | "reject" | "defer", "decided_by": "owner", "note": null}`

- `approve`：在该人格下一个事件开始前提交新版本 Bk+1 并调和状态（当前无未关闭事件则立即提交，返回 `committed`；否则返回 `approved`，`POST /episodes` 建新事件时先提交）。新版本 `origin = evolution`，被改条目的 `evidence_refs` 追加 `candidate:<id>`；若当前版本已比候选的基准版本新，数值修订按变化量叠加。
- `reject` / `defer`：候选保留（`deferred` 之后仍可再决定）。当前实现不会自动重新评估：其证据已被引用，不会再进入新的候选。
- 重复同一决定无副作用；对已决定的候选做不同决定 409 `candidate_decided`。
- 候选还返回 `episode_id`（触发反思的事件）、`created_at`、`decided_at`。
- 候选状态全集：`awaiting_owner` `approved` `committed` `rejected` `deferred` `pending_verification` `pending_realization` `no_commit`。

### 演化规则（服务配置，每个命名空间一份）

- **每个事件关闭后都完整审查一次，每次都可能演化**（2026-10-19 用户确认）：本事件的证据即可形成候选，不必等多个事件。
- 证据强度：跨多个事件方向一致为 `strong`；只来自本事件为 `limited`，先把适用范围缩小到证据覆盖处再测试。
- 最低证据：同一构念、同一原因的主人反馈 ≥3 条，或状态—行为监测中同一方向的持续偏离；达不到则 `defer`，证据跨事件累积。
- 每学期（可配置周期）上限：L1 每分面 ±0.10；L2 每项 ±0.20；L3 只追加带条件的描述，至多 2 条。
- 冻结副本测试：目标 / 相似 / 范围外情境各 2 个，新旧版本相同状态与记忆起点，标准事前固定；测试输出不作为证据。

## 7. 素材蒸馏（Anima A1）

把任意文本素材蒸馏成初始信念 B0。流程与规则见 `未修复.md` §2；以下为接口。

| 接口 | 说明 |
|---|---|
| `POST /v1/distillations` `{title}` | 新建，返回 Distillation（`stage = draft`） |
| `GET /v1/distillations` / `GET /v1/distillations/{id}` | 列表（新的在前）/ 单个：阶段 `stage`、步骤 `step`、目标、素材、进度 `progress`、用量 `usage`、错误 |
| `POST /v1/distillations/{id}/sources` `{name, text}` | 上传一份 UTF-8 文本（≤ 200 万字），按换行切成 ≤ 3000 字的片段；仅 `draft` 可用，否则 409 |
| `GET /v1/distillations/{id}/characters` | 候选说话人（行首"名字："出现 ≥ 2 次），按次数排序 |
| `POST /v1/distillations/{id}:preview` `{name, aliases}` | 相关片段数、字数、提及次数、预计调用次数与输入 token |
| `POST /v1/distillations/{id}:start` `{target:{name, aliases}, persona_id, language}` | 仅 `draft` / `failed` 可用（409）。初始蒸馏的标题改为目标角色名。流程：逐段抽取（特质证据标注所属分面）→ 大五某个维度的特质证据少于 3 条时，挑提到人物最多的 6 段只针对该维度补查 → 归纳（特质按大五维度各一次）→ 复核。没有片段提到目标 → 422 `no_mentions`。目标与上次相同时为续跑：只重试失败的片段；目标不同则清空证据重新筛选 |
| `GET /v1/distillations/{id}/entries` | 条目列表：`entry`（BeliefEntry）、`status`、`original_text`、`review_note`、`evidence`（编号与原句） |
| `GET /v1/distillations/{id}/evidence/{ev:<n>}` | 原句、说明、所属素材、所在片段全文与原句位置 |
| `PATCH /v1/distillations/{id}/entries/{entry_id}` `{status?, text?, scope?}` | `status`：`accepted` / `rejected` / `proposed`；改写 `text` 即视为通过（`edited`），首次改写时保留 `original_text` |
| `POST /v1/distillations/{id}/entries` `{layer, construct, construct_id, text, scope}` | 新增条目（`source = configured`，`status = added`） |
| `POST /v1/distillations/{id}:commit` | 把 `accepted` / `edited` / `added` 的条目写为 B0（已存在且未演化的人格会被替换；已演化 → 409 `persona_evolved`），被引用的原句作为 material（`ref = ev:<n>`）；没有可导入的条目 → 422 `nothing_accepted`。审阅与再次导入在 `committed` 后仍可进行 |

- `stage`：`draft` → `running`（`step`：`extracting` → `inducing` → `reviewing`）→ `review` → `committed`；`running` 中失败 → `failed`。
- 每次模型调用记录在 `model_calls`，`action_id` 为 `distill:<id>/seg<n>`、`distill:<id>/<construct>`、`distill:<id>/review`；`usage` 由此汇总。
- 抽取的原句必须逐字出现在片段中（只容忍空白差异），否则丢弃；归纳条目只能引用本类已核对的证据，没有证据的条目丢弃。
- 邮箱与 8 位以上数字在原句、说明与条目文字中替换为"［已遮蔽］"。

## 8. 桌宠聊天（Anima A2）

一段聊天就是一个 `episode`（`episode_id` 以 `chat-` 开头），参与者为人格 `self` 与主人 `owner`（不是人格）。主人的话记为观察，人格的回答是一次行动（固定 2 次调用），生成后立即提交。下列情况结束一段聊天：闲置 `PERSONA_CHAT_IDLE_MINUTES`（默认 10）分钟、满 40 条、客户端调用 `chat:end`。结束即关闭事件并排队课后整理，下一段聊天会召回这些记忆。

### `POST /v1/personas/{persona_id}/chat:say`

```json
{"text": "今天好累啊", "persona_name": "悟空", "owner_name": "主人"}
```

返回 `{"session_id", "reply": ChatTurn}`，在模型写完台词时就返回；状态、复核与依据随后在后台写完并提交，`/v1/actions/{action_id}/explanation` 在此之前返回 404，聊天记录里这句也在提交后才出现。`ChatTurn`：`seq`、`speaker`（`owner` / `persona`）、`text`、`at`、`action_id`（人格的回答才有，可用于 `/v1/actions/{action_id}/explanation`）、`emotion`（`calm happy excited surprised curious confused thoughtful agreeing embarrassed worried sad angry inspired` 之一，客户端映射为像素表情）。

每句回答是一次 `calls: 1` 的行动（§3），即一次模型调用；`emotion` 由服务端把模型写的心情词映射为上述之一（近义词就近归类，认不出的为 `calm`）。同一人格的话按顺序回答：上一句提交前，下一句、`chat:end` 都会等待。生成失败返回 502/503，主人那句话留在这段聊天里，下一句照常继续。

### `GET /v1/actions/{action_id}/state`

这句回答所依据的人格状态 Z_t：`{"action_id", "persona_id", "state": PersonaState, "state_issue"}`。在回答存档前（台词刚显示的几秒内）返回 404；台词已显示而其余输出失败时 `state` 为空、`state_issue` 说明原因。桌宠聊天记录里点它的话显示"它当时的内心"。

### `POST /v1/personas/{persona_id}/chat:end`

结束当前这段聊天，返回该段 `ChatSession`；没有进行中的聊天时返回 `null`。

### `GET /v1/personas/{persona_id}/chats?limit=20`

最近的聊天，新的在前：`[{"session_id", "status", "started_at", "ended_at", "turns": [ChatTurn]}]`。

## 9. 人格展示与演化蒸馏（Anima A4）

### 人格名册（切换与删除）

| 接口 | 说明 |
|---|---|
| `GET /v1/personas` | `{"items": [PersonaCard], "max": 5}`。`PersonaCard`：`persona_id`、`name`（最近一次导入它的初始蒸馏的角色名，没有则为 ID）、`k`、`entries`（已知条目数）、`created_at`、`chats`（聊天段数）、`last_chat_at`；最近聊过的在前 |
| `DELETE /v1/personas/{id}` | 永久删除：版本与条目、material、行动与状态、记忆（含关于它的关系记忆）、监测、反馈、候选、反思、发件箱，以及只有它参与的事件（聊天）与其中的观察、模型调用记录；它的演化蒸馏一并删除，**初始蒸馏保留**（可重新导入，聊天与记忆不会回来）。先等它正在存档的回复与课后整理完成；有蒸馏或演化正在运行 → 409 `persona_busy`；不存在 → 404 |
| `DELETE /v1/personas/{id}/all-data` | 显式完整清理，返回 `{"status":"deleted_all"}`。在上述删除范围上，同时删除本命名空间内与该 persona_id 关联的**全部初始及演化蒸馏项目**、上传素材副本、片段、证据、审阅条目及这些蒸馏的模型调用记录；一个事务完成。人物已删除但仍有关联蒸馏项目时也可调用；人物及关联项目均不存在 → 404 `persona_not_found`，任一关联项目运行中 → 409 `persona_busy`。不删除其他人物、其他命名空间、共享事件或磁盘上的原始素材文件。独立路由避免旧服务忽略查询参数而误报完整删除成功。 |

每个命名空间最多 `PERSONA_MAX_PERSONAS`（默认 5）个人格：新建人格的导入、蒸馏提交与蒸馏 `:start`（新人格 ID）超出时返回 409 `persona_limit`，`:start` 在调用模型之前就拒绝；已有人格的再次导入不受限。

### 版本与依据

| 接口 | 说明 |
|---|---|
| `GET /v1/personas/{id}/history` | 版本列表（新的在前）：`version_id`、`k`、`base_version_id`、`origin`（`construction` / `evolution` / `correction`）、`committed_at`、`entries`（条数）、`changes`（相对基准版本：`entry_id`、`layer`、`construct_id`、`change` = `added` / `changed` / `removed`、`before`、`after`；B0 为空） |
| `GET /v1/personas/{id}/materials?refs=ev:1,ev:2` | 条目 `evidence_refs` 对应的原文 `{ref: text}`（随版本保存的 material；最多 500 个） |
| `POST /v1/personas/{id}/versions/{version_id}:restore` | 回到旧版本：把它的条目复制成新版本（`origin = correction`），什么都不删除。先结束该人格进行中的聊天；已是当前版本 → 409 `already_active` |

### 演化（蒸馏的演化形态）

演化是 `kind = evolution` 的蒸馏，复用 §7 的进度、审阅、提交接口：

| 接口 | 说明 |
|---|---|
| `GET /v1/personas/{id}/evolution:preview?persona_name=` | 自当前版本提交以来：`sessions`、`owner_lines`、`persona_lines`、`deviations`（同一条目同一方向在 ≥2 段聊天中出现的监测偏差组数）、`estimated_calls`、`enough`（有主人的话或反复偏差）、`running`（未完成的演化 ID 或 null） |
| `POST /v1/personas/{id}/evolutions` `{persona_name}` | 新建草稿：自动收集素材（每段聊天一份 `kind = chat`，反复偏差一份 `kind = monitoring`），`base_version_id` 为当前版本。每个人格同时只能有一个未完成的演化 → 409 `evolution_open` |
| `POST /v1/distillations/{id}/sources` | 可追加主人的新素材（`kind = material`，按目标名筛选片段） |
| `POST /v1/distillations/{id}:start` | 同 §7；`persona_id` 必须是该演化的人格。没有素材 → 422 `no_sources` |
| `GET /v1/distillations/{id}/entries` | 修改建议：`entry` 为修改后的条目，`before` 为基准版本中的条目（新增为 null），`reason` 为写给主人的理由，`evidence` 只列本次找到的原文 |
| `POST /v1/distillations/{id}/entries/{entry_id}:try` | 试答对比：基准版本与"只加这一条修改"的版本各回答同一问题（从空状态起步，共 4 次调用）。返回 `{situation, before, after}` |
| `POST /v1/distillations/{id}:commit` | 先结束该人格进行中的聊天，再把接受的修改应用到基准版本，写为 `k+1`（`origin = evolution`）；返回 `k`。基准版本已不是当前版本 → 409 `version_moved`；人格处于其他未关闭事件 → 409 `episode_open` |
| `POST /v1/distillations/{id}:discard` | 放弃：演化在提交前（draft / failed / review）；初始蒸馏只在还没产出条目时（draft / failed）。其余 → 409 `not_discardable` |
| `GET /v1/distillations?kind=evolution` | 列表默认只列 `initial`（工作台） |

流程与约束：
- 抽取（`prompts/evolve_extract.md`，每片段 1 次）：聊天记录中**只有主人的话可以作为证据**，程序核对引文位于以"主人："开头的行内，否则丢弃——人格自己的台词由现有信念生成，用作证据只会自我强化。偏差记录与新素材整行可引。
- 修订（`prompts/evolve_revise.md`，每个有证据的类别 1 次）：对本类现有条目给出 `revise` / `add`。程序约束：L1 只改 `baseline`、L2 改 `baseline` / `satisfaction` / `frustration`，每次变化截到 L1 ±0.10、L2 ±0.20；L3 只能在原文后追加一句（每次至多 2 条），不能新增；只能修订 `supported` 且可修改的条目；每条至少引用一条已核对的证据；无变化的丢弃；同一条目只取第一条修订。
- 复核（`prompts/evolve_review.md`，1 次）：只看这次改动是否有依据、是否改得太多、是否前后矛盾。
- 提交后，条目的 `evidence_refs` 追加本次引用，引文作为 material 保存，可由 `materials` 读取。

## 10. 模型服务设置（桌宠设置页）

| 接口 | 说明 |
|---|---|
| `GET /v1/settings/model` | `{backend, base_url, model, disable_thinking, key_set, ready, key_hint, source}`。`ready`：已有 Key（或是开发用的 Fake 后端），桌宠据此决定是否提醒填写；`key_hint` 只给末 4 位（"…abcd"），Key 本身从不返回；`source` 为 `env`（环境变量 / .env）或 `saved`（设置页） |
| `PUT /v1/settings/model` `{base_url, model, api_key?, disable_thinking}` | 保存到 `PERSONA_MODEL_FILE`（默认 `data/model.json`，权限 600，覆盖环境变量的四项）并立即换用，不用重启。不带 `api_key` 表示保留原 Key；`""` 表示删除 Key（回到环境变量的后端；默认 openai 无 Key 即"未配置"）。`base_url` 须以 http(s):// 开头 |
| `POST /v1/settings/model:test` | 同样的请求体，用这些设置（不带 Key 时用已保存的）发一次很小的 JSON 请求：`{ok, latency_ms, message}`，失败时给出"API Key 不对""接口地址或模型名不对"等中文说明 |

**未配置与被拒**（桌宠据此提醒主人去设置页）：

- 后端默认 `PERSONA_MODEL_BACKEND=openai`。没有 Key 时，需要模型的接口——`chat:say`、`actions:prepare`、蒸馏 `:start`、条目 `:try`、`evolutions`、`reflections`、反思版本 `:try`——立即返回 `412 model_not_configured`，不发请求、不留记录。`fake` 只用于测试和开发。
- 模型服务返回 401/403（Key 不对或没权限）、402 或带额度字样的 429（额度不足）、404（地址或模型名不对）时不重试，返回 `503 model_rejected`，`message` 以"模型服务拒绝了请求："开头并指向设置页。后台的蒸馏、反思因此失败时，`error` 是同一句话。

`disable_thinking`：DeepSeek V4（TokenHub）默认开启思考，需要关闭；其他 OpenAI 兼容服务可能不认识这个参数，可在设置页取消。`/v1/runtime` 显示当前实际使用的模型。

## 11. 自我反思（演化的主要入口）

人格回顾自当前版本以来的聊天，写反思日记与发现，拟出不同程度的演化版本，**主人审批后**才成为新版本。

| 接口 | 说明 |
|---|---|
| `GET /v1/personas/{id}/reflection:preview?persona_name=` | `{since_version, since, sessions, owner_lines, deviations, enough, open}`；`open` 为未完成（running / ready）的反思 ID |
| `POST /v1/personas/{id}/reflections` `{persona_name}` | 在后台开始（2 次模型调用）。没有主人说的话也没有反复偏差 → 422 `nothing_to_reflect`；已有未完成的 → 409 `reflection_open` |
| `GET /v1/reflections/{id}` / `GET /v1/personas/{id}/reflections?limit=` | `Reflection`：`status`（running → ready → approved / declined；running → failed）、`diary`（第一人称反思日记）、`findings`（`id` F1…、`what`、`meaning`、`layer`、`entry_id`、`refs` 聊天行 L… / 偏差 D…）、`versions`（`key` A/B/C、`title` 微调 / 适度 / 明显、`summary`、`changes`：`entry_id`、`before`、`after`、`reason`、`evidence` [{id, who, text}]）、`chosen`、`committed_version_id` |
| `POST /v1/reflections/{id}/versions/{key}:try` | 当前版本与该版本各回答同一问题：`{situation, before, after}` |
| `POST /v1/reflections/{id}:approve` `{version}` | 审批采用：先结束进行中的聊天，写为 `k+1`（`origin = evolution`），依据的聊天原句作为 material（`rf:<id>:L…`）保存。版本不存在 → 422；已决定 → 409 `reflection_decided`；基准已不是当前版本 → 409 `version_moved` |
| `POST /v1/reflections/{id}:decline` | 都不采用：人格不变，日记保留 |

程序检查：每条发现至少引用一句主人说的话或在 ≥2 段聊天中反复出现的偏差（它自己的话只能帮助回想）；每处改动引用有效发现，并受演化上限约束（强弱每次 ±0.10 / ±0.20，L3 只能追加）。A 至多 2 处、叙事身份至多追加 1 句；B 至多 6 处、追加至多 2 句、不新增；C 至多 8 处、可新增条目。没有有效改动的版本不出现。
